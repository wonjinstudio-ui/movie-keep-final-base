# 과제를 하며 정리한 내용

### 1. 새로고침 후 Firebase 데이터를 Store에 다시 반영하는 이유

Store에 담긴 데이터는 새로고침하면 초기화됩니다. 그래서 Firebase에서 로그인 정보와 찜 목록을 다시 가져와 Store에 넣어야 화면에 표시할 수 있습니다.

### 2. DB 저장 성공 후 Store를 갱신하는 이유

Store부터 바꾸면 저장에 실패해도 화면에는 저장된 것처럼 보일 수 있습니다. DB 저장이 끝난 뒤 Store를 바꿔야 실제 데이터와 화면이 같아집니다.

### 3. 빈 메모 저장과 찜 삭제의 차이

빈 메모를 저장하면 메모 내용만 없어지고 찜은 남아 있습니다. 찜을 삭제하면 해당 찜 기록 자체가 없어집니다.

### 4. 복합 UNIQUE와 외래 키의 역할

userId와 movieId에 UNIQUE를 함께 걸면 같은 사용자가 같은 영화를 중복해서 찜할 수 없습니다. 외래 키는 없는 영화를 찜하지 못하게 하고, 찜에서 사용 중인 영화가 삭제되는 것도 막아줍니다.

### 5. 전체 집계와 사용자별 집계의 차이

전체 집계는 조건에 맞는 데이터를 모두 합쳐 개수를 구합니다. 사용자별 집계는 사용자마다 나눠서 각각 몇 개인지 구합니다.

### 6. API 개수를 배열 길이로 계산하는 이유

개수를 숫자로 직접 적으면 찜이 늘거나 줄 때마다 따로 고쳐야 합니다. favorites.length를 사용하면 현재 배열에 들어 있는 찜 개수를 그대로 응답할 수 있습니다.

선택 과제는 구현하지 않았습니다.
